# mcp/ backlog

**All of these should be built as `type: "remote"` MCP servers (a persistent HTTP process opencode connects to) from the start, not `type: "local"` (opencode-spawned over stdio)** — `oracle/` was originally built local/stdio and converted to remote/HTTP later (2026-09-14, see `mcp/oracle/README.md`'s Design and Status sections for why and how); the later servers below shouldn't repeat that detour. Reuse `oracle/server.js`'s pattern: Node's built-in `http` plus `@modelcontextprotocol/sdk`'s `StreamableHTTPServerTransport` in stateless mode (`sessionIdGenerator: undefined`, a fresh `Server`/transport pair per request), no extra HTTP framework dependency needed.

- [x] **Loki** — done 2026-09-14. `mcp/loki/` exposes `loki_query_range`/`loki_labels`/`loki_label_values` against the Loki HTTP query API (just `fetch`, no driver dependency, as planned), `type: "remote"` from the start. Tested end-to-end against a real Loki instance in the docker sandbox (`docker/docker-compose.loki.yml`) — see `mcp/loki/README.md`'s Status section and `docs/feature-points/14-loki-mcp-server.md`.
- [ ] `loki/`'s relative/naive time-param resolution (`resolveTimeParam()` in `mcp/loki/server.js`, added 2026-09-15 for agent-friendliness - see `mcp/loki/README.md`) - `now`/`now-<duration>`/naive-local-time parsing was verified standalone (node -e sanity check, not committed as a test) but not yet exercised against a real Loki instance or covered by `mcp/loki/loki.test.mjs`. Add cases there and re-run `./tests/run-all.sh` before relying on this in production.
- [ ] `oracle/`'s `auditQuery()` hook — still a no-op by design (see `mcp/oracle/README.md`'s design section for why); not urgent, do it later. Rule-based (regex/keyword denylist) or LLM-based (mirroring `plugins/llm-review-gate/llm-review-gate.ts`), or both — undecided.
- [x] `oracle/`/`loki/` offline dependency install — was tracked here as blocked (no way to `npm install` `@modelcontextprotocol/sdk`/`oracledb` on the offline target machine). Resolved 2026-09-17: the target machine, while lacking public internet, has a working internal npm registry (confirmed by Franco, a full mirror of public npm, not a curated subset) — so a plain `npm install` in SETUP.md steps 6/7 resolves these directly, no vendoring needed.
- [ ] Redis — official `redis/mcp-redis` exists but defaults to read/write; would need trimming to a read-only tool set (or an ACL-based read-only Redis user) before use here.
- [ ] MySQL — several community MCP servers exist; pick one that's actually read-only at the SQL layer, not just by convention, before adopting.
- [ ] xxl-job — no existing implementation anywhere (confirmed via [xuxueli/xxl-job#3775](https://github.com/xuxueli/xxl-job/issues/3775), open since 2025-08-11, unresolved). Would mean reading xxl-job-admin's internal AJAX endpoints directly, no public API docs to go from. Read-only (job/log status) only — never expose trigger/kill.

Secondary candidates raised but not yet worth their own line above: Nacos/Apollo (config center, read-only), RocketMQ/Kafka (topic lag / consumer offsets), SkyWalking/Zipkin (trace lookup), Jenkins/GitLab CI (build status) — all fit the same "internal-ops, read-only, one server per LAN system" shape as the four above.
