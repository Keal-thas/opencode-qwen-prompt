- **Oracle singleton first-time-startup race (deferred).** If two worktrees both race to bring up the shared Oracle container for the very first time ever on a machine (`docker/dev.sh` does this idempotently before every `opencode-dev` invocation — see `docker/docker-compose.oracle.yml`), one `docker compose up -d` succeeds and the other gets a real, non-zero-exit `Conflict: container name already in use` error. Once Oracle is already running, later concurrent `up -d` calls from any worktree are fine (idempotent reconcile). Narrow window, low blast radius (just retry) — a `flock`-style lock around "ensure Oracle is up" in `docker/dev.sh` would close it if it ever actually bites.

- **Docker image tag (`opencode-qwen-prompt-dev:latest`) build race across worktrees (deferred).** The image is deliberately global/shared across all worktrees (rebuilding a multi-GB toolchain image per worktree would be wasteful) — so it sits outside the per-worktree isolation `docker/dev.sh` gives everything else. If two worktrees have different uncommitted `Dockerfile` content and both run `docker/dev.sh build` around the same time, whichever finishes last silently wins the `:latest` tag — the other's successful build just becomes untagged/dangling, and that worktree's next `docker/dev.sh run` quietly uses someone else's image instead of the one it just built, with no error.
