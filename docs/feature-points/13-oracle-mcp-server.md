# oracle mcp server

Lives in `mcp/oracle/`. An MCP server exposing one tool, `oracle_query`, that runs an arbitrary SQL statement against a configured Oracle database — full passthrough by design (no read-only enforcement, no keyword filtering), with an `auditQuery()` extension point left as a no-op for a rule-based or LLM-based check to be added later. One connection opened and closed per request rather than a shared/pooled connection — see `mcp/oracle/README.md` for why. Built directly against `@modelcontextprotocol/sdk` and `oracledb` (thin mode, no Oracle Instant Client needed), same hand-rolled-against-the-raw-API style as `plugins/`.

**Tested:** manually, inside the `docker/` sandbox — `npm install` + `node --check` for syntax, then two rounds of a full MCP stdio round-trip (`tools/list` + `tools/call`) against a real `@modelcontextprotocol/sdk` `Client`. First round used a deliberately unreachable Oracle host to exercise the error path, and caught a real bug (a connection failure was crashing out as a raw MCP protocol error instead of the intended `{success: false, error}` tool result — `oracledb.getConnection()` was outside the `try` block), now fixed. Second round ran against a real throwaway `gvenzl/oracle-free:slim` container on the sandbox's docker network: `SELECT`, `CREATE TABLE`, `INSERT`, a fresh request's `SELECT *` confirming the insert persisted (validates `autoCommit: true` across the per-request connection boundary), `DROP TABLE`, and a query against a nonexistent table for the DB-level error path (`ORA-00942`). Not yet added to `tests/` as an automated test.
