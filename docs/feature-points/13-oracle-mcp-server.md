# oracle mcp server

Lives in `mcp/oracle/`. An MCP server exposing one tool, `oracle_query`, that runs an arbitrary SQL statement against a configured Oracle database, built directly against `@modelcontextprotocol/sdk` and `oracledb` (thin mode, no Oracle Instant Client needed), same hand-rolled-against-the-raw-API style as `plugins/`. Design rationale (full passthrough by design, one connection per request, `autoCommit: true`, the no-op `auditQuery()` extension point) lives in `mcp/oracle/README.md`'s "Design, and why it looks the way it does" section — that's the canonical reference, cross-referenced here rather than duplicated.

**Tested:** manually at first, inside the `docker/` sandbox — `npm install` + `node --check` for syntax, then two rounds of a full MCP stdio round-trip (`tools/list` + `tools/call`) against a real `@modelcontextprotocol/sdk` `Client`. First round used a deliberately unreachable Oracle host to exercise the error path, and caught a real bug (a connection failure was crashing out as a raw MCP protocol error instead of the intended `{success: false, error}` tool result — `oracledb.getConnection()` was outside the `try` block), now fixed. Second round ran against a real Oracle instance on the sandbox's docker network: `SELECT`, `CREATE TABLE`, `INSERT`, a fresh request's `SELECT *` confirming the insert persisted (validates `autoCommit: true` across the per-request connection boundary), `DROP TABLE`, and a query against a nonexistent table for the DB-level error path (`ORA-00942`).

Now also automated: `mcp/oracle/oracle.test.mjs` (see `tests/README.md`), covering the same cases above plus a regression test for the connection-failure bug. Wired into `tests/run-in-container.sh`, which runs as part of `./tests/run-all.sh`. **Written but not yet executed** (2026-09-13) — added in a pass that deliberately skipped running Docker to verify it; run `./tests/run-all.sh` to confirm it actually passes before relying on it.
