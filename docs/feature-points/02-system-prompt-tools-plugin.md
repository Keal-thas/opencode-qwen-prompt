# system-prompt-tools.ts plugin

Source lives in `plugins/system-prompt-tools/system-prompt-tools.ts`. Hooks `experimental.chat.system.transform` to dump the fully-assembled system prompt actually sent to the model (all blocks, including opencode's own `<env>` block) to `~/.local/share/opencode/last-system-prompt.txt` on every request — the only way to confirm the override is really taking effect against the real model, since there's no other visibility into what gets sent. Written in TypeScript against `@opencode-ai/plugin`'s `Plugin` type (the official SDK), matching `plugins/hook-logger/hook-logger.ts`/`plugins/llm-review-gate/llm-review-gate.ts`.

**Packaging:** ships as its own npm package — `plugins/system-prompt-tools/package.json` + the committed, pre-packed `opencode-system-prompt-tools-1.0.0.tgz` (regenerate with `npm pack` in that directory after editing the source; `tests/unit/plugins-tarball.test.mjs` fails the build if it drifts). On the target machine, install it by extracting that tarball into opencode's own package cache (`$CACHE_DIR/packages/opencode-system-prompt-tools@1.0.0/`, SETUP.md step 4) and referencing it in `opencode.json`'s `plugin` array as the bare `"opencode-system-prompt-tools@1.0.0"` — no path, no `file:` spec. `plugins/hook-logger/` and `plugins/llm-review-gate/` use the same mechanism as independent packages (SETUP.md step 5), so installing one does not require the others. Confirmed against a real opencode install, with outbound network cut, that this resolves instantly with no network round-trip and no npm/bun needed on `PATH`; see `docker/docker-notes.md`'s "Plugin dependency pre-warming" section for the verification recipe. This rests on opencode's undocumented cache-key behavior, so re-verify after bumping the pinned opencode version. Tradeoff: unlike `deploy/system-prompt.txt`, editing `plugins/system-prompt-tools/system-prompt-tools.ts` no longer takes effect immediately in the docker sandbox via the live bind mount — it needs `npm pack` plus an image rebuild first, same as `plugins/hook-logger/`/`plugins/llm-review-gate/`.

**Tested:** `tests/unit/system-prompt-tools.test.mjs` — dump content/header format (model/session/block-count), and that each request overwrites rather than appends (the dump always reflects the latest request). Its shipped packaging is covered by `tests/unit/plugins-tarball.test.mjs`.
