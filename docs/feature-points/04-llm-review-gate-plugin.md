# llm-review-gate.ts plugin

Lives in `plugins/`. Gates `bash` tool calls behind an LLM safety review: before a command runs, it's sent to a hidden internal opencode session for an ALLOW/BLOCK verdict, layered on top of (not replacing) opencode's own permission config. Fails open on review errors/timeouts by default (`FAIL_OPEN_ON_ERROR`, configurable). Never reviews its own internal review session's own calls (no recursion). Written in TypeScript against `@opencode-ai/plugin`'s `Plugin` type (the official SDK) rather than an untyped raw hook object.

**Deployment (changed 2026-09-15, install mechanism changed 2026-09-16, briefly de-packaged then re-packaged 2026-09-17):** own npm package at `plugins/llm-review-gate/` (`package.json` + the committed `opencode-llm-review-gate-1.0.0.tgz`), installed on the target machine by extracting the tarball into opencode's own package cache and referencing it as a bare `opencode-llm-review-gate@1.0.0` (SETUP.md step 5), purely opt-in and independently of `hook-logger/` (previously shipped in one shared tarball, couldn't be installed separately — see `docs/feature-points/02-system-prompt-tools-plugin.md` for that history) — worth calling out specifically since it changes real runtime behavior (an extra hidden model call before every `bash` invocation), unlike `hook-logger/`'s passive logging.

**Tested:** `tests/unit/llm-review-gate.test.mjs` — ALLOW/BLOCK paths, non-gated tools skipped entirely, self-recursion guard, fail-open on review error or an unparseable verdict. Driven with a fake opencode `client`, so no real session or model server is needed. Its shipped packaging (the committed `opencode-llm-review-gate-1.0.0.tgz`) is separately covered by `tests/unit/plugins-tarball.test.mjs`.
