# Deployment docs

`SETUP.md` is written to be executed *by an agent* on the target machine (no internet, git-bash on Windows) — copies files in, merges the `agent` config key, optionally installs the viewer plugin (step 4) and the hook-logger/llm-review-gate plugins (step 5, purely opt-in — general-purpose tooling unrelated to the prompt override, not installed by default), optionally wires in the Oracle, Loki, and Memory MCP servers (steps 6–8, see feature points 13/14/15), verifies, reports back. Both plugin steps extract a committed npm tarball by hand straight into opencode's own package cache and reference it by a bare `name@version` in the `plugin` array — no path, no `file:` spec — see `docs/feature-points/02-system-prompt-tools-plugin.md`. `SETUP-notes.zh.md` is a separate Chinese human-facing walkthrough of the same steps, not meant to be executed literally.

**Tested:** indirectly — `tests/unit/config-consistency.test.mjs`'s SETUP.md/example-config drift check is the one piece of SETUP.md's *content* under test. The step-by-step procedure itself can only really be validated by actually running it on the target machine, which is out of reach from here.
